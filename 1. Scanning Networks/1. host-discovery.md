# 🧪 Scanning Networks — Practical

> **CEH v13 | Module: Scanning Networks**
>

The objective of this practical is to understand how different network scanning techniques can be used to determine whether a target host is **alive/reachable** and how TCP scanning techniques can be used to identify **open ports**.

| 🌐 IP | IP Protocol Ping |

# 02 — 🟠 ARP Ping Scan

## 🎯 Objective

ARP Ping Scan uses **ARP requests** to determine whether a host is active on the local Ethernet network.

Nmap uses the `-PR` option for ARP Ping.

### Command

```bash
nmap -PR 192.168.100.16
```

### 📤 Representative Output

```text
Starting Nmap
Nmap scan report for 192.168.100.16
Host is up (0.00xxs latency).

MAC Address: XX:XX:XX:XX:XX:XX

Nmap done: 1 IP address (1 host up) scanned
```

### 🔍 What Happened?

```text
Kali
  │
  │ ARP Request
  ▼
192.168.100.16
  │
  │ ARP Response
  ▼
Kali
```

If the target responds to the ARP request, Nmap can identify the host as **up**.

> 💡 **Key Point:**  
> ARP discovery is particularly useful on a **local Layer 2 network**.

---

# 03 — 🔵 ICMP Echo Ping

## 🎯 Objective

ICMP Echo Ping sends an **ICMP Echo Request** to the target and waits for an **ICMP Echo Reply**.

Nmap uses `-PE` for ICMP Echo Ping.

### Command

```bash
nmap -PE 192.168.100.16
```

### 📤 Representative Output

```text
Starting Nmap
Nmap scan report for 192.168.100.16
Host is up (0.00xxs latency).

Nmap done: 1 IP address (1 host up) scanned
```

### 🔍 What Happened?

```text
Kali
  │
  │ ICMP Echo Request
  ▼
Target
  │
  │ ICMP Echo Reply
  ▼
Kali
```

The reply indicates that the target is reachable.

> 💡 This is the same basic mechanism used by the traditional `ping` utility.

---

# 04 — ⏱️ ICMP Timestamp Ping

## 🎯 Objective

ICMP Timestamp Ping uses an **ICMP Timestamp Request** to determine whether the target responds to this type of ICMP traffic.

Nmap uses `-PP` for ICMP Timestamp Ping.

### Command

```bash
nmap -PP 192.168.100.16
```

### 📤 Representative Output

```text
Starting Nmap
Nmap scan report for 192.168.100.16
Host is up.

Nmap done: 1 IP address (1 host up) scanned
```

### 🔍 What Happened?

Nmap sent an ICMP Timestamp request.

If the target provides the expected response, Nmap can use it as an indication that the host is reachable.

> ⚠️ **Note:**  
> Modern operating systems and firewalls may block ICMP Timestamp requests.

---

# 05 — 🎭 ICMP Address Mask Ping

## 🎯 Objective

ICMP Address Mask Ping uses an **ICMP Address Mask Request**.

Historically, this mechanism could be used to obtain subnet-mask information from a target.

Nmap uses `-PM` for ICMP Address Mask Ping.

### Command

```bash
nmap -PM 192.168.100.16
```

### 📤 Representative Output

```text
Starting Nmap
Nmap scan report for 192.168.100.16
Host is up.

Nmap done: 1 IP address (1 host up) scanned
```

### 🔍 What Happened?

Nmap attempted to send an ICMP Address Mask request.

If the target responds, the response can provide an indication that the system is reachable.

> ⚠️ **Note:**  
> Many modern systems do not respond to ICMP Address Mask requests.

# 06 — 🌐 ICMP Ping Sweep

## 🎯 Objective

A **Ping Sweep** checks multiple IP addresses to identify which hosts are alive.

Nmap uses `-sn` for host discovery without performing a normal port scan.

### Command

```bash
nmap -sn 192.168.100.0/24
```

### 📤 Representative Output

```text
Starting Nmap
Nmap scan report for 192.168.100.1
Host is up.

Nmap scan report for 192.168.100.10
Host is up.

Nmap scan report for 192.168.100.16
Host is up.

Nmap scan report for 192.168.100.20
Host is up.

Nmap done: 256 IP addresses (4 hosts up) scanned
```

### 🔍 What Happened?

Nmap checked the hosts within:

```text
192.168.100.0/24
```

and identified the systems that responded.

### Network Flow

```text
192.168.100.1   ──► ?
192.168.100.2   ──► ?
192.168.100.3   ──► ?
      ...
192.168.100.16  ──► ✅ Host Up
      ...
192.168.100.254 ──► ?
```

> 💡 **Key Point:**  
> `-sn` is primarily used for **host discovery**, not normal port scanning.

# 07 — 🔴 TCP SYN Ping

## 🎯 Objective

TCP SYN Ping sends a **TCP SYN packet** to the target.

It can be useful for host discovery when ICMP-based discovery is filtered.

Nmap uses `-PS` for TCP SYN Ping.

### Command

```bash
nmap -PS 192.168.100.16
```

A specific port can also be specified:

```bash
nmap -PS80 192.168.100.16
```

### 📤 Representative Output

```text
Starting Nmap
Nmap scan report for 192.168.100.16
Host is up.

Nmap done: 1 IP address (1 host up) scanned
```

### 🔍 Basic Flow

```text
Kali
  │
  │ TCP SYN
  ▼
Target
  │
  │ Response
  ▼
Kali
```

The response can provide information indicating that the host is reachable.

> ⚠️ **Important:**  
> `-PS` is **TCP SYN Ping for host discovery**.  
> It is different from `-sS`, which performs a TCP SYN port scan.

### 🔍 What Happened?

# 🔎 11 — TCP SYN Half-Open Scan

> ## 🚨 Moving from Host Discovery → Port Scanning

Until now, we were mainly checking whether the **host is alive**.

Now we will check which **TCP ports are open**.

---

## 🎯 Objective

TCP SYN Scan is also called a **Half-Open Scan**.

Nmap uses the `-sS` option.

The scanner sends a SYN packet and analyzes the response without normally completing the full TCP connection.

### Command

```bash
nmap -sS 192.168.100.16
```

### 📤 Representative Output

```text
Starting Nmap
Nmap scan report for 192.168.100.16
Host is up.

PORT     STATE  SERVICE
22/tcp   open   ssh
80/tcp   open   http
139/tcp  open   netbios-ssn
445/tcp  open   microsoft-ds

Nmap done: 1 IP address (1 host up) scanned
```

### 🔄 Basic TCP Flow

```text
Scanner                         Target
   │                               │
   │────── SYN ──────────────────►│
   │                               │
   │◄──── SYN/ACK ────────────────│
   │                               │
   │────── RST ──────────────────►│
   │                               │
   ▼                               ▼
Port identified as OPEN
```

If the target responds with `SYN/ACK`, the port is generally considered **open**.

The scanner normally does not complete the full TCP connection, which is why it is called a **Half-Open Scan**.

> 💡 **Remember:**  
> `-sS` = **TCP SYN Port Scan**  
> `-PS` = **TCP SYN Host Discovery**

# 🔗 12 — TCP Connect Scan

## 🎯 Objective

TCP Connect Scan attempts to establish a **complete TCP connection** with the target.

Nmap uses the `-sT` option.

### Command

```bash
nmap -sT 192.168.100.16
```

### 📤 Representative Output

```text
Starting Nmap
Nmap scan report for 192.168.100.16
Host is up.

PORT     STATE  SERVICE
22/tcp   open   ssh
80/tcp   open   http
139/tcp  open   netbios-ssn
445/tcp  open   microsoft-ds

Nmap done: 1 IP address (1 host up) scanned
```

### 🔄 Basic TCP Flow

```text
Scanner                         Target
   │                               │
   │────── SYN ──────────────────►│
   │                               │
   │◄──── SYN/ACK ────────────────│
   │                               │
   │────── ACK ──────────────────►│
   │                               │
   │   TCP Connection Established  │
   │                               │
   ▼                               ▼
```

If the TCP connection is successfully established, Nmap can identify the port as **open**.

---

# ⚔️ SYN Scan vs Connect Scan

| Feature | 🔴 SYN Scan | 🔵 Connect Scan |
|---|---|---|
| Nmap Option | `-sS` | `-sT` |
| Type | Half-Open | Full Connect |
| Full TCP Connection | ❌ Normally not completed | ✅ Completed |
| Raw Packets | Used | Not required in the same way |
| Common Use | TCP Port Scanning | TCP Port Scanning |
| Privileges | Usually requires elevated privileges | Can work without raw packet privileges |

### 🧠 Easy Way to Remember

```text
-sS
 ↓
SYN
 ↓
SYN/ACK
 ↓
RST
 ↓
Half-Open

-sT
 ↓
SYN
 ↓
SYN/ACK
 ↓
ACK
 ↓
Full Connection
```

# 🧠 14 — Practical Observations

During this practical, multiple protocols were used to determine whether the target system was reachable.

The important concept is:

```text
Different Discovery Method
          ↓
Different Protocol / Packet
          ↓
Target Response
          ↓
Nmap Analyzes Response
          ↓
Host Reachability
```

No single discovery technique works in every network.

For example:

```text
ICMP Discovery
      │
      ├── Blocked ──► Try TCP Discovery
      │
      ├── Allowed ──► Host Response
      │
      └── Filtered ─► Try Another Technique
```

The result depends on:

- Firewall configuration
- Operating system
- Network architecture
- Protocol filtering
- IDS/IPS controls
- Host configuration

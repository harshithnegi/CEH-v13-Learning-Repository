# 1. Performing Host Discovery

## Objective

Host discovery ka purpose ye determine karna hai ki target system **reachable/alive** hai ya nahi.

Different discovery techniques different protocols use karti hain, jaise **ARP, ICMP, TCP, UDP aur IP protocols**. Is practical mein hum Nmap ke different host-discovery options ko target machine par test karenge.

---

## Step 1: Start a Root Shell

Kuch Nmap scanning techniques ko raw packets send karne ke liye elevated privileges ki zarurat ho sakti hai.

```bash
sudo su
```

Verify:

```bash
whoami
```

Expected:

```text
root
```

# 2. ARP Ping Scan

## Objective

ARP Ping Scan local Ethernet network par ARP requests ka use karke determine karta hai ki target host reachable hai ya nahi.

Nmap mein ARP ping ke liye `-PR` option use hota hai.

## Command

```bash
nmap -PR 192.168.100.16
```

### Representative Output

```text
Starting Nmap
Nmap scan report for 192.168.100.16
Host is up (0.00xxs latency).

MAC Address: XX:XX:XX:XX:XX:XX

Nmap done: 1 IP address (1 host up) scanned
```

### What Happened?

Nmap ne target ko ARP request ke through probe kiya.

Agar target ne ARP response diya, Nmap ne host ko **up/reachable** identify kiya.

> **Key Point:** `-PR` ARP Ping ke liye mainly local Ethernet networks par useful hai.

Nmap mein ICMP Echo Ping ke liye `-PE` option use hota hai.

## Command

```bash
nmap -PE 192.168.100.16
```

### Representative Output

```text
Starting Nmap
Nmap scan report for 192.168.100.16
Host is up (0.00xxs latency).

Nmap done: 1 IP address (1 host up) scanned
```

### What Happened?

Nmap ne target ko ICMP Echo Request bheja.

Target ne response diya, isliye Nmap ne host ko **up** report kiya.

# 6. ICMP Ping Sweep

## Objective

Ping Sweep ka purpose ek single host ke bajay **multiple IP addresses** ko check karke live hosts identify karna hai.

Nmap mein `-sn` host discovery scan ke liye use hota hai.

## Command

```bash
nmap -sn 192.168.100.0/24
```

### Representative Output

```text
Starting Nmap
Nmap scan report for 192.168.100.1
Host is up.

Nmap scan report for 192.168.100.10
Host is up.

Nmap scan report for 192.168.100.16
Host is up.

Nmap scan report for 192.168.100.20
Host is up.

Nmap done: 256 IP addresses (4 hosts up) scanned
```

### What Happened?

Nmap ne `192.168.100.0/24` network ke addresses ko scan karke live/reachable hosts identify kiye.

`-sn` ka purpose **host discovery** hai; by default iska main purpose port scanning nahi hai.

# 11. TCP SYN Half-Open Scan

## Objective

Ab hum host discovery se **port scanning** ki taraf move karenge.

TCP SYN Scan ko **half-open scan** bhi kaha jata hai because scanner normally complete TCP connection establish nahi karta.

Nmap mein TCP SYN Scan ke liye `-sS` option use hota hai.

## Command

```bash
nmap -sS 192.168.100.16
```

### Representative Output

```text
Starting Nmap
Nmap scan report for 192.168.100.16
Host is up.

PORT     STATE    SERVICE
22/tcp   open     ssh
80/tcp   open     http
139/tcp  open     netbios-ssn
445/tcp  open     microsoft-ds

Nmap done: 1 IP address (1 host up) scanned
```

### What Happened?

Nmap ne TCP SYN packets ke through ports ko probe kiya.

Typical behavior:

```text
Scanner                Target

   SYN  ───────────────►
        ◄────────────── SYN/ACK
   RST  ───────────────►
```

Agar SYN/ACK response milta hai, port ko generally **open** identify kiya ja sakta hai.

Scanner connection ko normally complete nahi karta, isi wajah se ise **half-open scan** kaha jata hai.

> **Important:** `-sS` host discovery option nahi hai. Ye **TCP port scanning** ke liye use hota hai.

# 12. TCP Connect Scan

## Objective

TCP Connect Scan complete TCP connection establish karne ki koshish karta hai.

Nmap mein TCP Connect Scan ke liye `-sT` option use hota hai.

Ye scan commonly tab use hota hai jab raw packet privileges available nahi hote.

## Command

```bash
nmap -sT 192.168.100.16
```

### Representative Output

```text
Starting Nmap
Nmap scan report for 192.168.100.16
Host is up.

PORT     STATE    SERVICE
22/tcp   open     ssh
80/tcp   open     http
139/tcp  open     netbios-ssn
445/tcp  open     microsoft-ds

Nmap done: 1 IP address (1 host up) scanned
```

### What Happened?

TCP Connect Scan normal TCP connection establish karne ki koshish karta hai.

Basic process:

```text
Scanner                Target

   SYN  ───────────────►
        ◄────────────── SYN/ACK
   ACK  ───────────────►
        TCP Connection Established
```

Agar connection successfully establish hota hai, Nmap port ko **open** identify kar sakta hai.

---

# 13. Difference: SYN Scan vs Connect Scan

| Feature | SYN Scan (`-sS`) | Connect Scan (`-sT`) |
|---|---|---|
| Type | Half-open | Full TCP connection |
| TCP connection | Normally not completed | Completed |
| Speed | Generally faster | Generally slower |
| Privileges | Usually requires elevated privileges | Can work without raw packet privileges |
| Detection | Can be monitored/detected | Full connection is established |
| Purpose | TCP port discovery | TCP port discovery |

# 14. Host Discovery Techniques Summary

The techniques performed in this practical can be summarized as follows:

| Technique | Nmap Option | Purpose |
|---|---|---|
| ARP Ping | `-PR` | Discover hosts using ARP |
| ICMP Echo | `-PE` | Discover hosts using ICMP Echo |
| ICMP Timestamp | `-PP` | Discover hosts using ICMP Timestamp |
| ICMP Address Mask | `-PM` | Discover hosts using ICMP Address Mask |
| Ping Sweep | `-sn` | Discover live hosts |
| TCP SYN Ping | `-PS` | Discover hosts using TCP SYN |
| TCP ACK Ping | `-PA` | Discover hosts using TCP ACK |
| UDP Ping | `-PU` | Discover hosts using UDP |
| IP Protocol Ping | `-PO` | Discover hosts using IP protocols |
| TCP SYN Scan | `-sS` | TCP half-open port scan |
| TCP Connect Scan | `-sT` | TCP full-connect port scan |

# 15. Practical Observation

During host discovery, different protocols were used to determine whether the target system was reachable.

The important observation is that **no single discovery technique works in every environment**.

For example:

```text
ICMP blocked
      ↓
Try TCP-based discovery
      ↓
TCP filtered
      ↓
Try UDP / ARP where applicable
```

The response depends on the target operating system, firewall rules, network configuration, and IDS/IPS controls.

---

# 16. Key Takeaways

- `-PR` → ARP Ping
- `-PE` → ICMP Echo
- `-PP` → ICMP Timestamp
- `-PM` → ICMP Address Mask
- `-sn` → Host Discovery / Ping Scan
- `-PS` → TCP SYN Ping
- `-PA` → TCP ACK Ping
- `-PU` → UDP Ping
- `-PO` → IP Protocol Ping
- `-sS` → TCP SYN / Half-Open Scan
- `-sT` → TCP Connect Scan

> **Important:** `-PR`, `-PE`, `-PP`, `-PM`, `-PS`, `-PA`, `-PU`, `-PO`, and `-sn` are used for **host discovery**, while `-sS` and `-sT` are **port-scanning techniques**.

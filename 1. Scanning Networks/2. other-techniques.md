# 01 — 🔗 TCP Connect Scan

## 🎯 Objective

TCP Connect Scan attempts to establish a **complete TCP connection** with the target.

It is useful when we want to identify open TCP ports using a normal TCP connection.

Nmap uses the `-sT` option.

### Command

```bash
nmap -sT 192.168.100.16
```

### 📤 Representative Output

```text
Starting Nmap
Nmap scan report for 192.168.100.16
Host is up.

PORT     STATE  SERVICE
22/tcp   open   ssh
80/tcp   open   http
139/tcp  open   netbios-ssn
445/tcp  open   microsoft-ds

Nmap done: 1 IP address (1 host up) scanned
```

### 🔍 What Happened?

The TCP three-way handshake is completed:

```text
Scanner                         Target
   │                               │
   │──────── SYN ────────────────►│
   │◄─────── SYN/ACK ─────────────│
   │──────── ACK ────────────────►│
   │                               │
   │    TCP Connection Created     │
```

Nmap can then determine whether the TCP port is accessible.

> 💡 **Remember:**  
> `-sT` = **TCP Connect Scan**

# 02 — ⚙️ Service & Version Detection

## 🎯 Objective

After discovering open ports, we may want to know **which service and software version** is running on those ports.

Nmap uses the `-sV` option for service and version detection.

### Command

```bash
nmap -sV 192.168.100.16
```

### 📤 Representative Output

```text
Starting Nmap
Nmap scan report for 192.168.100.16

PORT     STATE  SERVICE      VERSION
22/tcp   open   ssh          OpenSSH 8.x
80/tcp   open   http         Apache httpd 2.4.x
139/tcp  open   netbios-ssn  Samba
445/tcp  open   microsoft-ds Samba

Nmap done: 1 IP address (1 host up) scanned
```

### 🔍 What Happened?

Nmap first identifies open ports and then probes those services to determine their:

- Service name
- Application/software
- Version
- Additional service information

### Flow

```text
Open Port
    ↓
Service Detection
    ↓
Service Identification
    ↓
Version Detection
    ↓
More Detailed Enumeration
```

> 💡 Example:
>
> Knowing `80/tcp` is open tells us a service is accessible.
>
> `-sV` may provide additional information such as the web server software and version.

# 03 — 💻 OS Detection

## 🎯 Objective

OS detection attempts to identify the **operating system** running on the target.

Nmap uses the `-O` option.

### Command

```bash
nmap -O 192.168.100.16
```

### 📤 Representative Output

```text
Starting Nmap
Nmap scan report for 192.168.100.16

Device type: general purpose
Running:
Microsoft Windows

OS details:
Microsoft Windows Server

Network Distance: 1 hop

Nmap done: 1 IP address (1 host up) scanned
```

### 🔍 What Happened?

Nmap sends and analyzes different probes and responses.

It compares characteristics of the target's network stack with known OS fingerprints.

```text
Nmap
  │
  │ Multiple probes
  ▼
Target
  │
  │ Responses
  ▼
Nmap
  │
  ▼
Analyze TCP/IP characteristics
  │
  ▼
Possible OS Identification
```

> ⚠️ OS detection is fingerprint-based, so the result may not always be exact.

# 04 — 🕵️ TCP SYN / Half-Open Scan

## 🎯 Objective

TCP SYN Scan is commonly known as a **Half-Open Scan**.

Instead of completing the full TCP connection, Nmap sends a SYN and analyzes the response.

Nmap uses:

```text
-sS
```

### Command

```bash
nmap -sS 192.168.100.16
```

### 📤 Representative Output

```text
Starting Nmap
Nmap scan report for 192.168.100.16

PORT     STATE  SERVICE
22/tcp   open   ssh
80/tcp   open   http
139/tcp  open   netbios-ssn
445/tcp  open   microsoft-ds

Nmap done: 1 IP address (1 host up) scanned
```

### 🔍 TCP Flow

```text
Scanner                         Target
   │                               │
   │──────── SYN ────────────────►│
   │◄─────── SYN/ACK ─────────────│
   │──────── RST ────────────────►│
   │                               │
   ▼                               ▼
   Port identified as OPEN
```

The TCP connection is not normally completed.

> 💡 **Remember:**
>
> `-sS` → TCP SYN / Half-Open Scan  
> `-sT` → TCP Connect / Full Connection Scan

# 05 — 🎄 XMAS Scan

## 🎯 Objective

XMAS Scan is a TCP scan that sends a packet with multiple TCP flags set.

Nmap uses:

```text
-sX
```

### Command

```bash
nmap -sX 192.168.100.16
```

### 📤 Representative Output

```text
Starting Nmap
Nmap scan report for 192.168.100.16

PORT     STATE         SERVICE
22/tcp   open|filtered ssh
80/tcp   open|filtered http
139/tcp  open|filtered netbios-ssn
445/tcp  open|filtered microsoft-ds

Nmap done: 1 IP address (1 host up) scanned
```

### 🔍 Why is it called XMAS?

The scan sets multiple TCP flags, creating a packet with many "lights" turned on, similar to a Christmas tree.

Common flags involved are:

```text
FIN + PSH + URG
```

### Concept

```text
TCP Packet
┌─────────────────────────────┐
│ FIN │ PSH │ URG │           │
└─────────────────────────────┘
```

The target's response is analyzed to infer the state of the port.

> ⚠️ **Important:**  
> Results can vary depending on the target operating system and firewall behavior.

# 06 — 📢 Verbose Scan

## 🎯 Objective

Verbose mode does not represent a completely different scanning technique.

Instead, it tells Nmap to provide **more information during the scan**.

Nmap uses:

```text
-v
```

### Command

```bash
nmap -v 192.168.100.16
```

For even more verbosity:

```bash
nmap -vv 192.168.100.16
```

### 📤 Representative Output

```text
Starting Nmap
Initiating Ping Scan
Scanning 192.168.100.16
Host is up.

Initiating SYN Stealth Scan
Discovered open port 22/tcp
Discovered open port 80/tcp
Discovered open port 445/tcp

PORT     STATE  SERVICE
22/tcp   open   ssh
80/tcp   open   http
445/tcp  open   microsoft-ds

Nmap done: 1 IP address (1 host up) scanned
```

### 🔍 What Happened?

Verbose mode displays additional information about what Nmap is doing during the scan.

```text
Normal Scan
    ↓
Basic Results

Verbose Scan (-v)
    ↓
Additional Scan Information
    ↓
More Visibility During Execution
```

> 💡 **Remember:**  
> `-v` changes the **amount of information displayed**, not the fundamental scan type.

# 07 — 🔍 Maimon Scan

## 🎯 Objective

Maimon Scan is a TCP scan technique that uses a specially crafted TCP packet involving the **FIN and ACK flags**.

Nmap uses:

```text
-sM
```

### Command

```bash
nmap -sM 192.168.100.16
```

### 📤 Representative Output

```text
Starting Nmap
Nmap scan report for 192.168.100.16

PORT     STATE         SERVICE
22/tcp   open|filtered ssh
80/tcp   open|filtered http
139/tcp  open|filtered netbios-ssn

Nmap done: 1 IP address (1 host up) scanned
```

### 🔍 Basic Concept

The Maimon scan sends a TCP probe using a combination of:

```text
FIN + ACK
```

Nmap analyzes the response from the target.

```text
Nmap
 │
 │ FIN + ACK
 ▼
Target
 │
 │ Response
 ▼
Nmap
 │
 ▼
Analyze Port State
```

> ⚠️ **Note:**  
> Maimon Scan behavior can vary significantly between operating systems and firewall implementations.

# 08 — ⚫ NULL Scan

## 🎯 Objective

A NULL Scan sends a TCP packet with **no TCP flags set**.

Nmap uses:

```text
-sN
```

### Command

```bash
nmap -sN 192.168.100.16
```

### 📤 Representative Output

```text
Starting Nmap
Nmap scan report for 192.168.100.16

PORT     STATE         SERVICE
22/tcp   open|filtered ssh
80/tcp   open|filtered http
139/tcp  open|filtered netbios-ssn
445/tcp  open|filtered microsoft-ds

Nmap done: 1 IP address (1 host up) scanned
```

### 🔍 What Makes It Different?

A normal TCP packet usually contains specific TCP flags.

A NULL scan sends a packet with:

```text
FIN = 0
SYN = 0
RST = 0
PSH = 0
ACK = 0
URG = 0
```

In simple terms:

```text
TCP Packet
┌─────────────────────────────┐
│ No TCP Flags Set            │
└─────────────────────────────┘
```

Nmap analyzes how the target responds to the unusual packet.

> ⚠️ **Important:**  
> NULL, FIN, and XMAS scans rely heavily on TCP/IP implementation behavior, so results can vary between operating systems.

# 09 — 🚀 Aggressive Scan

## 🎯 Objective

Aggressive Scan combines multiple Nmap features to gather **more information in a single scan**.

Nmap uses:

```text
-A
```

### Command

```bash
nmap -A 192.168.100.16
```

### 📤 Representative Output

```text
Starting Nmap
Nmap scan report for 192.168.100.16

PORT     STATE  SERVICE  VERSION
22/tcp   open   ssh      OpenSSH 8.x
80/tcp   open   http     Apache httpd 2.4.x
445/tcp  open   microsoft-ds

Device type: general purpose
Running: Microsoft Windows

OS details:
Microsoft Windows Server

Service Info:
OS: Windows
```

### 🔍 What Does `-A` Enable?

Aggressive detection enables several advanced detection features, including:

- OS detection
- Version detection
- Script scanning
- Traceroute

Conceptually:

```text
             -A
              │
      ┌───────┼────────┐
      │       │        │
      ▼       ▼        ▼
     OS      Version   NSE
 Detection  Detection Scripts
      │       │        │
      └───────┼────────┘
              │
              ▼
          Traceroute
```

> 💡 **Key Point:**  
> `-A` is useful when you want a broader picture of the target instead of performing only a basic port scan.

# ⚠️ Important Notes

### 1. Scan Results Can Vary

The exact output depends on:

- Target operating system
- Open ports
- Firewall configuration
- IDS/IPS
- Network configuration
- Service configuration

Therefore, the outputs shown above are **representative examples**, not guaranteed exact results.

### 2. Special TCP Scans

XMAS, Maimon, and NULL scans rely on how the target's TCP/IP stack handles unusual TCP packets.

Their behavior can vary between operating systems and security devices.

### 3. Aggressive Scan

`-A` performs multiple detection techniques together and can generate considerably more traffic than a basic scan.
